# Synthea Health Data Project

A PostgreSQL project built on synthetic patient data generated by [Synthea](https://github.com/synthetichealth/synthea). It covers designing a relational schema, loading CSV data, validating it, and analyzing it with SQL, with a Power BI dashboard planned on top.

> **Note:** All data is synthetic. No real patient information is used, and results should not be read as clinical findings.

## Dataset

Five Synthea CSV tables are loaded:

| Table | Description | Rows |
|---|---|---|
| `organizations` | Hospitals and clinics | 1,127 |
| `payers` | Insurers | 10 |
| `providers` | Clinicians, linked to an organization | 5,056 |
| `patients` | Patient demographics | 1,163 |
| `encounters` | Patient visits, linked to a patient, organization, provider, and payer | 61,459 |

`encounters` is the central table. Each row references a patient, organization, provider, and payer through foreign keys.

## Setup

1. Install PostgreSQL and make sure `psql` is available.
2. Place the Synthea CSV files in `data/csv/`. The files are not included in this repository.
3. Create the database:
   ```sql
   CREATE DATABASE synthea;
   ```
4. Connect to it with `psql`, then move to the project root:
   ```
   \c synthea
   \cd '/path/to/this/project'
   ```
5. Build the schema and load the data, in this order:
   ```
   \i sql/01_schema.sql
   \i sql/02_load.sql
   ```
6. Run `sql/03_validate.sql` in any SQL client to check the load.

`02_load.sql` uses `\copy`, which only works in `psql`. Tables load in dependency order (parents before children). Re-running `01_schema.sql` drops and recreates all tables, so run it before reloading.

## Data Validation

`03_validate.sql` checks that the data loaded correctly and makes sense:

- **Row counts** match the load output
- **Spot checks** confirm values landed in the correct columns
- **NULL checks** separate expected blanks (such as `deathdate` for living patients) from problems
- **Sanity checks** look for impossible values, such as a death before a birth, an encounter ending before it starts, or negative costs
- **Category checks** confirm labels such as race and gender are clean and consistent
- **Duplicate checks** look for repeated patients and IDs
